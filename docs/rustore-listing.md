# RuStore: карточка приложения, анкеты, чек-лист владельца

Черновик для публикации Android-клиента в RuStore. Тексты — на вычитку владельцу.
Политика конфиденциальности — `deployments/privacy.html`
(https://mail.letotam.ru/privacy, редакция 14.11.2026). Анкета о данных ниже составлена
строго по ней: поменялась политика — анкету правим в том же коммите.

Требования RuStore сверены 2026-11-14 по справке для разработчиков (ссылки внизу).
Интерфейс Консоли меняется — если пункт называется иначе, ищите по смыслу.

## Сборка

- В RuStore идёт вариант **`rustore`** (RuStore Push):
  `ANDROID_HOME=… ./gradlew assembleRustoreRelease` →
  `~/.cache/builds/gradle/ddmail-android/app/outputs/apk/rustore/release/app-rustore-release.apk`.
  Вариант `hms` — для AppGallery (`docs/huawei-appgallery.md`).
- Пакет `ru.letotam.ddmail`. Подпись — постоянный ключ `~/.config/ddmail-android/release.jks`,
  сертификат SHA-256
  `53:07:94:04:20:DE:9F:B5:F7:04:44:C4:E1:58:33:94:BB:89:98:28:F8:17:47:E4:92:CF:72:38:FE:0B:17:F5`.
  **Потеря ключа — обновлять приложение в RuStore будет нечем.** Держите копию
  `release.jks` и `keystore.properties` вне станций.
- Версия — `versionName`/`versionCode` в `mobile/android/app/build.gradle.kts`. Каждая
  выкладка — новая версия (на 2026-11-14 — 0.0.41, code 41).
- Push: без `~/.config/ddmail-android/rustore.properties` (`project_id=…`) сборка
  собирается, но push выключен, и новая почта приходит фоновой проверкой примерно раз в
  15 минут. На 2026-11-14 файла нет: проект RuStore Push ещё не заведён (см. чек-лист).

## Карточка

| Поле (лимит RuStore) | Значение |
|---|---|
| Название (до 30) | ddmail. Совпадает с подписью под иконкой на телефоне (`app_name`). В App Store клиент называется «DDMail» — выберите одно написание для всех сторов |
| Краткое описание (до 80) | Почта, календарь, задачи и контакты: беседы вместо списка писем |
| Категория | основная — **«Полезные инструменты»** (по справке туда входят «связь, планировщики задач»). Дополнительную не указывать. «Общение» — только для мессенджеров, «Бизнес-сервисы» — для CRM, учёта и внутренних систем компаний |
| Возрастная категория | **12+** (рекомендация). Своего контента у приложения нет, но оно показывает переписку пользователя, где может оказаться что угодно, и загружает картинки с внешних сайтов по разрешению. 0+ формально тоже возможна, а 12+ снимает спор с модерацией. Решает владелец |
| Поисковые теги (до 5) | почта, email, календарь, контакты, задачи |
| Контакты разработчика | email legal@mfml.ru, сайт https://mail.letotam.ru/ |
| Политика конфиденциальности | https://mail.letotam.ru/privacy |
| Иконка | 512×512 PNG/JPG, до 3 МБ, фон без прозрачности по всей площади, тот же рисунок, что у установленного приложения. Готовая — `mobile/store-assets/icon-512.png` (её готовит параллельная задача про иконку, сверить, что попала в git) |

**Полное описание** (до 4000 знаков; после 2000 текст сворачивается — главное в начале):

ddmail — почтовый клиент для сервера ddmail и любых ящиков IMAP/SMTP. Письма собраны в беседы: переписка с человеком или группой — одна лента, как в мессенджере, а не плоский список писем.

• Беседы вместо писем: ответы, вложения и история переписки — в одной ленте.
• Папки диалогов с правилами по адресу получателя и домену собеседника — те же, что в настольной версии.
• Цвет беседы по адресу, на который пришло письмо: рабочее и личное видно сразу.
• Несколько учётных записей: сервер ddmail и обычные ящики IMAP/SMTP.
• Картинки из писем загружаются только с вашего разрешения.
• Спам — в отдельной папке, без уведомлений.
• Календарь (день, неделя, месяц, год), напоминания о встречах, задачи и контакты; внешние календари и адресные книги по CalDAV/CardDAV.
• Складные телефоны и планшеты: на большом экране список и беседа рядом.

Для учётной записи ddmail нужен сервер ddmail. Пароль учётной записи ddmail на телефоне не хранится, только токен сессии. Пароли ящиков IMAP/SMTP хранятся на телефоне в зашифрованном виде (Android Keystore) и передаются только серверам этих ящиков. Рекламы, аналитики и трекеров в приложении нет.

> Не писать в карточке «бесплатно», «навсегда», «лучший» и подобное: RuStore не
> пропускает превосходные степени, а обещаний на будущее политика не даёт.

## Скриншоты

Требования RuStore для телефона: **не меньше 3** (за раз загружается 1–10), PNG или JPG,
**до 3 МБ**, не больше 2160×3840; рекомендуемое соотношение — 16:9 (для вертикальных 9:16).
Картинки меньше рекомендуемого растягиваются, больше — обрезаются. Планшетные скриншоты
(до 5 МБ, тоже минимум 3) нужны, только если отмечать поддержку планшетов.

**Размер — 1080×1920 (9:16), PNG.** Снимок с Mate XT в сложенном виде — 1008×2232
(≈9:20), RuStore его обрежет. Поэтому снимок масштабируется по высоте (≈867×1920) и
ставится по центру холста 1080×1920 с фоном приложения `#F6F7F9`. Те же файлы подходят
AppGallery.

**Учётка — только демо** `review@mail.letotam.ru` (вымышленные люди, домены
`example.com`/`example.org`; заводится отдельной задачей). Снимки с настоящей почты не
годятся: на них персональные данные корреспондентов (152-ФЗ).

| № | Экран | Что в кадре |
|---|---|---|
| 1 | Почта — список бесед | табы папок диалогов, цветные метки адресов, непрочитанные |
| 2 | Беседа | лента пузырей с ответами и картинкой-вложением, строка ввода |
| 3 | Новое письмо | поиск-адресат с подсказками контактов и «Написать по адресу…» |
| 4 | Календарь — неделя или месяц | события этой недели |
| 5 | Контакты | список с буквенными разделами, открытая карточка |
| 6 | Задачи | список задач с отметками |
| 7 (необяз.) | Разложенный Mate XT | список и беседа рядом. Для телефонного раздела — тоже 1080×1920 (обрезать по колонке нельзя, лучше пропустить); для планшетного — 1920×1080 |

Снимать: `adb.exe -s <serial> exec-out screencap -p > shot.png`. Размер экрана телефона
командой `wm size` **не менять** — Mate XT меняет его сам при складывании, принудительное
значение искажает изображение.

## Анкета «Безопасность данных пользователя»

Блок в Консоли из двух разделов. Основание — `deployments/privacy.html`.

### Чувствительные разрешения (нужно обоснование)

По справке RuStore из разрешений приложения чувствительные — два. Остальные (`INTERNET`,
`ACCESS_NETWORK_STATE`, `USE_EXACT_ALARM`, `RECEIVE_BOOT_COMPLETED`,
`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`, `FOREGROUND_SERVICE`, `WAKE_LOCK`) — «безопасные»,
их декларировать не нужно.

| Разрешение | Обоснование |
|---|---|
| `POST_NOTIFICATIONS` | Уведомления о новых письмах и напоминания о событиях календаря. Пользователь может отключить их в настройках системы. |
| `SCHEDULE_EXACT_ALARM` | Напоминания о встречах календаря в назначенное пользователем время (за N минут до события). Без точного будильника система откладывает напоминание. |

### Категории и типы данных

Консоль заполняет часть пунктов по манифесту — проверьте и дополните до списка ниже.

| Категория RuStore | Тип данных | Откуда (политика) |
|---|---|---|
| Личная информация | Адрес электронной почты | адреса и имена пользователей подключённых учётных записей |
| Личная информация | ID пользователей | имя пользователя учётки ddmail и подключённых ящиков |
| Сообщения | Электронные письма | письма: отправители, получатели, темы, тексты, вложения |
| Контакты | Контакты | контакты учётной записи |
| Календарь | События календаря | события календаря и задачи |
| Идентификаторы | ID устройства или другие идентификаторы | идентификатор устройства в сервисе доставки push; сервер хранит его до выхода из учётки |

Если в форме есть пояснения, указать: данные нужны только для работы приложения. Рекламы,
аналитики и трекеров нет. Письма, контакты и календарь хранятся у почтовых провайдеров
пользователя (сервер ddmail и подключённые им серверы) и в кэше на устройстве.
Третьим лицам данные не передаются. Сервис push получает только сигнал «есть новые
письма», без отправителя, темы и адресов. Соединения шифруются. Удаление учётной записи в
приложении удаляет с устройства её пароль или токен и кэш.

Пароли в анкете RuStore отдельного типа не имеют. Пароль ddmail на устройстве не
хранится. Пароли ящиков IMAP/SMTP и CalDAV/CardDAV хранятся на устройстве в Android
Keystore и уходят только своим серверам, разработчику не передаются.

## Модерация: доступ для проверки

Приложение без входа не работает. В поле для модератора (комментарий к версии) указать:

> Вход: на первом экране ввести `review@mail.letotam.ru`, нажать «Найти сервер», затем
> ввести пароль и «Войти». Учётка демонстрационная, данные вымышленные. Пожалуйста, не
> отправляйте с неё письма на реальные внешние адреса.

Пароль — из `~/.config/ddmail-ios/review-account.env` (общий с App Store; в git его нет),
вносится только в Консоль.

## Чек-лист владельца: консоль RuStore

1. **Аккаунт разработчика** — https://console.rustore.ru, вход через VK ID. Тип —
   физлицо, ИП/самозанятый или организация. Проверка — по шагам Консоли. Тип выбирается
   сразу: публиковать от организации позже — это другой аккаунт.
2. **Приложение:** «Приложения» → «Создать». Пакет `ru.letotam.ddmail`, название
   `ddmail`. Первый загруженный APK закрепляет ключ подписи, все обновления — тем же
   ключом (SHA-256 выше). APK собираю я и присылаю путь, загружаете вы.
3. **RuStore Push:** страница приложения → «Push-уведомления» → «Проекты» →
   создать проект:
   - пакет `ru.letotam.ddmail`;
   - SHA-256 подписи:
     `53:07:94:04:20:DE:9F:B5:F7:04:44:C4:E1:58:33:94:BB:89:98:28:F8:17:47:E4:92:CF:72:38:FE:0B:17:F5`;
   - создать **сервисный токен** проекта.
4. **Карточка:** тексты, категория, возраст, теги, контакты, иконка, политика — из
   разделов выше. Скриншоты — после демо-учётки.
5. **«Безопасность данных пользователя»** — по анкете выше.
6. **Цена/распространение:** бесплатно, страна — Россия (это настройка Консоли, не
   обещание в описании).

**Что прислать мне:**

| Что | Куда | Секрет? |
|---|---|---|
| ID проекта RuStore Push | можно в чат. Я положу его в `~/.config/ddmail-android/rustore.properties` (`project_id=…`) на обеих станциях и пересоберу `rustore` | нет |
| Сервисный токен проекта | **не в чат.** Положите в файл `~/.config/ddmail-android/rustore-service-token` на станции (вне git), оттуда я перенесу его в `push.rustore.service_token` конфига сервера `/etc/mailserver/config.yaml` | **да** |
| Подтверждение, что приложение создано и APK загружен | чат | нет |
| Решения: название (ddmail/DDMail), возраст (12+/0+) | чат | нет |

Чего **не** присылать: документы для верификации, логины и пароли от Консоли.
