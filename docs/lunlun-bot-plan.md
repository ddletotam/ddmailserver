# lunlun.email: регистрация и оплата через Telegram-бота

Решение владельца 2026-11-27. Сервис бесплатный для базовой почты, платные функции —
за звёзды Telegram. Карт, имён, телефонов сервис не видит.

## Правила

- **Регистрация только через бота.** Веб-регистрация для lunlun.email закрыта
  (`disable_registration` остаётся). Кнопка на сайте ведёт на `t.me/<бот>`.
- **Один аккаунт Telegram — один бесплатный адрес** `логин@lunlun.email`, логин на выбор.
  Повторная регистрация с того же Telegram невозможна; бан распространяется на Telegram ID.
- **Оплата всех функций — звёздами в боте** (`currency XTR`, без платёжного провайдера).
- Бот же — единственный канал восстановления: сброс пароля, статус, оплата, жалобы.

## Устройство

- **Бот — часть `mailserver`** (`internal/tgbot`), long polling, без вебхука и без
  отдельного сервиса: один бинарь, прямой доступ к базе. Токен — `telegram.bot_token` в
  `/etc/mailserver/config.yaml`, не в git.
- **Связь:** таблица `telegram_links` (`tg_user_id` уникален, `user_id`, дата, флаг бана).
  Из Telegram храним только ID и язык — без имени и username.
- **Аккаунт:** обычный пользователь (`kind = user`, `username` = логин) с адресом
  `логин@lunlun.email`. Значит, работает всё приложение DDMail (push, календарь,
  контакты); платные функции включаются флагами, а не другим типом учётки.
- **Пароль** генерирует бот, показывает один раз и удаляет сообщение через 10 минут.
  «Сбросить пароль» — кнопка в боте.
- **Условия:** `/start` → ссылка на условия и политику → кнопка «Принимаю». Без неё
  регистрации нет; дата согласия хранится.
- **Права:** таблица `entitlements` (`user_id`, функция, действует до). Проверка там, где
  функция используется. Лимиты сервера (`internal/db/limits.go`) становятся лимитами
  тарифа: бесплатный / платный.
- **Оплата:** `sendInvoice` / `createInvoiceLink` с `XTR` → `pre_checkout_query` (проверить,
  что заказ ещё актуален) → `successful_payment` → запись платежа
  (`telegram_payment_charge_id` — для возврата через `refundStarPayment`) → продление
  права. Помесячно — подписка звёздами (`subscription_period` 30 дней, продлевает Telegram).

## Логин

- 3–32 символа: латиница, цифры, `.` `-` `_`, начинается с буквы, без двух точек подряд.
- Уникален среди пользователей, ящиков и алиасов всех доменов сервера.
- Запрещены служебные и выдающие себя за других: `admin`, `root`, `postmaster`, `abuse`,
  `support`, `security`, `noreply`, `mailer-daemon`, `info`, `billing`, `help`,
  названия банков, госсервисов и платёжных систем (список в коде, пополняется).

## Защита от спама

Все домены отправляют с одного IP — один спамер портит доставку всем. Поэтому:

1. **Лимиты бесплатного ящика:** писем в час и в сутки, получателей в одном письме,
   разных получателей в сутки (спамер пишет многим разным — живой человек немногим).
2. **Прогрев:** первые 7 дней лимиты ниже.
3. **Проверка исходящих** тем же анализатором (`internal/parser`): высокий балл — письмо
   не уходит, ящик на проверку.
4. **Автостоп отправки** при всплеске отказов «нет такого адреса» и при жалобах; сообщение
   в бот владельцу ящика и администратору.
5. **Жалобы получателей:** Google Postmaster Tools, Яндекс и Mail.ru Postmaster (FBL),
   Microsoft SNDS. `abuse@` и `postmaster@lunlun.email` — существуют и читаются.
6. **Отдельный IP для бесплатных** (второй адрес на сервере): бесплатные отправляют с
   него, платные и свои домены — с основного. Испорченная репутация бесплатных не задевает
   платных.
7. **Поток регистраций:** общий потолок новых аккаунтов в час; превышение — пауза и
   сигнал администратору (защита от ферм Telegram-аккаунтов).
8. **Доверие:** оплатившие и Telegram Premium — обычные лимиты сразу.
9. **Контроль чёрных списков:** ежедневная проверка IP (Spamhaus и др.), сигнал в бот
   администратору.

## Этапы

1. Бот: `/start`, условия, выбор логина, создание аккаунта, пароль, сброс пароля.
   Сайт: кнопка регистрации → бот.
2. Тарифные лимиты и защита 1–4, 7; автостоп с сообщением в бот.
3. Права и оплата звёздами: каталог функций, счета, подписки, возвраты.
4. Отдельный IP для бесплатных, Postmaster/FBL, контроль чёрных списков.

## Решить владельцу

- Имя бота и токен (создать в @BotFather, токен положить на сервер — не в чат).
- Список платных функций и цены в звёздах; помесячно или навсегда.
- Бесплатный тариф: объём ящика, лимиты отправки.
- Что при окончании оплаты: сколько дней отсрочки; данные сохраняются, функция
  перестаёт работать (внешние ящики не синкаются, свой домен не принимает почту?).
- Неактивные бесплатные ящики: удалять ли через N месяцев без входа.
