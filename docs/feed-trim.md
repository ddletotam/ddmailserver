# Лента без истории и подписей (сервер)

В ленте беседы ценен только текст письма — плотность как у мессенджера.
Процитированная переписка (разделитель, шапка «кому/тема/когда», цитата) и
подпись (имя, должность, баннер, дисклеймер, подвал роботов) повторяют то, что
в ленте уже есть, и в длинной беседе занимают бо́льшую часть экрана. Сервер
отдаёт клиентам письмо без них.

**Вся обработка — только на сервере.** Клиенты (десктоп, Android, iOS) ничего
не режут и не схлопывают: показывают то тело, что отдал сервер. Хранимое
письмо не меняется: MIME, IMAP, DKIM — как были; оригинал доступен через
`/messages/{id}/source` («Исходник» в клиентах).

Код — `internal/feedtrim`, таблица — `message_feed` (миграция 064).

## Правило: срезаем только доказанное

Ни шаблонов цитат, ни регулярок «… писал:». Оба среза проверяются по почте,
которая у пользователя уже есть.

**История.** Предки письма — по `In-Reply-To` по цепочке (Яндекс 360 не ставит
`References`) и по `References`; ищутся в ящике пользователя вне спама и
корзины, Message-ID сравнивается без угловых скобок (свои отправленные хранятся
без них). Строки письма сравниваются с полным текстом предков по словесным
тройкам (переносы, `>`, NBSP и разметка не мешают). Срезается сплошной хвост
письма, совпадающий с предками, и шапка над ним, если в шапке есть адрес, имя,
время (в любом поясе) или тема предка — хотя бы два признака, или адрес/имя
плюс разделитель. Без опознанной шапки хвост срезается, только если покрывает
не меньше половины какого-то предка и над ним есть строка, которой в предках нет.
Не режем: предка нет в ящике; ответ вперемешку с цитатой; кроме цитаты ничего
не осталось.

**Подпись.** Хвост своего текста письма, который повторяется в большинстве
бесед отправителя (не меньше трёх; беседа — тема без Re:/Fwd:, обновления одной
встречи считаются одной). Если в повторяющемся хвосте есть строка «--»/«—»,
срез — с неё. У отправителя, с которым меньше трёх бесед, — только по
разделителю «-- » не дальше 40 строк от конца. Сравнение идёт со своими
строками прежних писем отправителя (`own_tail`).

**HTML** режется по узлу DOM, с которого начинается строка; опустевшие после
среза контейнеры (таблица подписи, `blockquote`) убираются.

## Когда считается

Триггер на `messages` кладёт новое письмо (и письмо со сменённым телом) в
`message_feed_queue`; фоновый обработчик разбирает очередь — любой путь записи
(MX, локальная доставка, копия в «Отправленных», IMAP APPEND, синхронизация
внешних учёток) покрыт. При старте сервера в очередь встают письма без версии и
посчитанные прежней версией алгоритма (`feedtrim.Version`; поменял правило —
подними версию). Пришло письмо, на которое уже отвечали, — ответы
пересчитываются: теперь их цитата доказуема.

## API

`POST /conversations/messages` отдаёт в `html` и `text` версию для ленты, если
в письме что-то срезано, и оригинал — если нет. Поле `trimmed` — что срезано:
`"history"`, `"signature"` (у нетронутого письма его нет).

Клиенты кэшируют тело навсегда, поэтому письмо, которое очередь ещё не
посчитала, считается прямо в запросе: из сервера тело уходит уже обрезанным.
Следствия, которые клиенты не исправляют (их не трогаем):

- тела, закэшированные клиентом до выката (24.11.2026), остаются оригиналами,
  пока клиент не перекачает их сам;
- если предок пришёл после того, как клиент забрал ответ, сервер ответ
  пересчитает, но клиент его уже закэшировал;
- «Переслать» в клиенте берёт тело из ленты — пересылается суть, без истории
  и подписи.

## Замер (ящик владельца, 2026-11-24, 2977 писем вне спама и корзины)

- ответов с предком в ящике — 296, история срезана у 80 (у остальных в основном
  роботы: совпадает только подвал); медиана среза — 64% текста письма;
- подпись срезана у 1591: подписи людей и подвалы рассылок/уведомлений;
- пересчёт всего ящика — 19 с.
