# План: администрирование сервера отдельно от пользователя

**Сценарий, ради которого всё:** админ берёт на обслуживание `example.com`, в DNS домена
прописывается наш сервер, админ создаёт ящик `vasya@example.com` и передаёт Васе
реквизиты. Вася в нашем вебе добавляет себе ещё одну учётку IMAP/SMTP, не зная, что это
тот же сервер. Ящик работает и в нашем почтовике, и в любом другом.

**Три входа:** веб — всегда только пользователь. IMAP и SMTP — пользователь (те же
реквизиты, что в вебе: IMAP отдаёт письма всех его учёток, SMTP проверяет отправку по
всем его учёткам) **или** ящик обслуживаемого домена (IMAP — письма ящика, SMTP —
отправка от этого ящика).

Решения владельца 2026-11-16 (по карточкам). Только сервер — клиенты (десктоп, iOS,
Android) не меняются, кроме того, что прямо сказано ниже.

## Решения

**Администратор**
- Отдельная учётка администратора: только `/admin`, без почты и агрегации. Чтобы читать
  почту, человек входит обычным пользователем.
- Админка — тот же сайт, раздел `/admin`; заложить настройку «пускать в `/admin` только
  с этих IP».
- Пользователей админ приглашает **ссылкой** (одноразовая, со сроком жизни): человек сам
  задаёт логин и пароль. Работает и при закрытой регистрации.
- Регистрация — три режима: открыта / закрыта / с предмодерацией (учётка работает после
  одобрения админа). Подтверждение email и капча — позже.
- Домены и ящики на них заводит **только администратор**.
- Ящик на локальном домене — самостоятельная сущность **со своим паролем**, как у любого
  почтового хостинга. Админ передаёт адрес и пароль; пользователь подключает ящик к себе
  по IMAP/SMTP, как любой внешний (модель входа — ниже). Один ящик могут подключить
  несколько пользователей.
- Удаление пользователя удаляет его агрегацию (подключения, настройки, кэш). Ящики на
  локальных доменах ему не принадлежат и остаются у админа.
- Блокировка пользователя закрывает **все** входы: веб, API клиентов, IMAP, SMTP,
  CalDAV/CardDAV, пароли приложений, push; открытые сессии рвутся. Почту на ящики,
  которые он подключил, сервер продолжает принимать.
- Лимиты первой версии: квота на ящик, квота на пользователя, лимит отправки, число
  внешних учёток. **По умолчанию все выключены** — включение и цифры только сознательным
  действием админа.
- Спам-фильтр (правила, белые/чёрные списки, веса проверок) настраивает админ на весь
  сервер. Пользователь в клиентах только помечает «спам / не спам».

**Пользователь (веб)**
- Убираем: чтение почты, отправку, поиск, «Удалённые» (vault), список писем «Спама»,
  просмотр событий и контактов.
- Остаётся: мои учётки (внешние ящики, календари CalDAV/ICS, адресные книги CardDAV —
  подключение и настройки), журнал синхронизации, профиль (язык, пароль, ключ
  восстановления, пароли приложений).

## Этапы

1. ✅ 2026-11-16 (d4a33d8). **Админ отдельно.** Тип учётки «администратор»; `/admin` и `/api/admin/*` пускают только
   её; журнал действий админа; ограничение `/admin` по IP (настройка, по умолчанию выкл).
   Перенос: на нашем сервере завести учётку администратора, у `lucky` снять флаг.
2. ✅ 2026-11-16. **Блокировка везде.** Проверка `is_banned` на всех протоколах и при выдаче токенов;
   разрыв сессий (WebSocket, IMAP IDLE).
3. **Ящики с паролем.** Подробный план — `docs/mailbox-accounts-plan.md` (ящик —
   хранилище-принципал со своим логином-адресом). Исходный порядок:
   1. **Правило входа** (до собственных паролей ящиков): логин с `@` на обслуживаемом
      домене — вход ящика; без `@` или с доменом самого сервера — вход пользователя.
      Переходный режим: не подошёл пароль ящика — проверяем по-старому, как вход
      пользователя (сейчас `AuthenticateProtocol` отбрасывает домен; на этом держатся
      опубликованные клиенты и демо-учётка ревью). Убрать, когда старые версии вымрут.
   2. **Клиенты:** автонастройка отвечает «это ящик — подключай по IMAP/SMTP», либо
      клиент после отказа во входе пользователем сам пробует IMAP. Во всех трёх клиентах,
      выпустить до включения паролей ящиков.
   3. **Пароль у ящика**; IMAP — письма только этого ящика; SMTP — From только сам ящик.
      Вход пользователя: IMAP — все его учётки, SMTP — From любой его учётки (внешние
      уходят через свой SMTP, как сейчас).
   4. **Подключение своего ящика как внешнего:** сервер видит, что хост — он сам, и
      связывает учётку пользователя с ящиком напрямую — письма хранятся один раз, спам
      и квоты считаются один раз. Пароль ящика проверяется, как при IMAP-входе, иначе
      можно подключить чужой ящик по одному адресу.
   5. **Перенос:** каждый текущий ящик становится самостоятельным с паролем, равным
      паролю владельца, у владельца — подключение к нему; никто ничего не замечает
      (включая `review@mail.letotam.ru`).
   - Push при входе ящиком в нашем приложении (режим IMAP) не приходит — только при
     входе пользователем. Блокировка пользователя не закрывает подключённые им ящики;
     ящик админ отключает отдельно.
4. ✅ 2026-11-16. **Админ: домены и ящики.** Все домены и ящики сервера, DNS-записи домена,
   создание/отключение/удаление ящика, смена пароля ящика.
5. ✅ частично 2026-11-16 (приглашения, одобрение, бан/удаление; список админов — позже). **Админ: пользователи.** Ссылки-приглашения, список, блокировка, удаление,
   одобрение при предмодерации.
6. ✅ частично 2026-11-16 (режим регистрации; спам-фильтр и лимиты — позже). **Настройки сервера.** Режим регистрации (в `system_settings`, без перезапуска;
   `security.disable_registration` в config — значение по умолчанию), спам-фильтр сервера,
   лимиты (всё выключено по умолчанию).
7. ✅ 2026-11-16 (спам-правила пока у пользователя — переедут к админу в этапе 6). **Чистка пользовательского веба.** Удалить страницы чтения/отправки; перед удалением
   проверить по коду клиентов, что они эти маршруты не зовут.

Каждый этап — отдельный коммит с тестами и выкаткой; поведение пользователя меняется
только на этапах 3 и 7.
