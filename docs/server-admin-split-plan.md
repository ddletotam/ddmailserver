# План: администрирование сервера отдельно от пользователя

Решения владельца 2026-11-16 (по карточкам). Только сервер — клиенты (десктоп, iOS,
Android) не меняются, кроме того, что прямо сказано ниже.

## Решения

**Администратор**
- Отдельная учётка администратора: только `/admin`, без почты и агрегации. Чтобы читать
  почту, человек входит обычным пользователем.
- Админка — тот же сайт, раздел `/admin`; заложить настройку «пускать в `/admin` только
  с этих IP».
- Пользователей админ приглашает **ссылкой** (одноразовая, со сроком жизни): человек сам
  задаёт логин и пароль. Работает и при закрытой регистрации.
- Регистрация — три режима: открыта / закрыта / с предмодерацией (учётка работает после
  одобрения админа). Подтверждение email и капча — позже.
- Домены и ящики на них заводит **только администратор**.
- Ящик на локальном домене — самостоятельная сущность **со своим паролем**, как у любого
  почтового хостинга. Админ передаёт адрес и пароль; пользователь подключает ящик к себе
  по IMAP/SMTP, как любой внешний, а сервер сам распознаёт, что ящик локальный (без
  сетевого круга). Один ящик могут подключить несколько пользователей.
- Удаление пользователя удаляет его агрегацию (подключения, настройки, кэш). Ящики на
  локальных доменах — не его собственность и остаются у админа. *(На карточке «удаление»
  был ответ «всё вместе», но он давался до решения «ящик с паролем»; при этой модели
  ящик пользователю не принадлежит — подтвердить.)*
- Блокировка пользователя закрывает **все** входы: веб, API клиентов, IMAP, SMTP,
  CalDAV/CardDAV, пароли приложений, push; открытые сессии рвутся. Почту на ящики,
  которые он подключил, сервер продолжает принимать.
- Лимиты первой версии: квота на ящик, квота на пользователя, лимит отправки, число
  внешних учёток. **По умолчанию все выключены** — включение и цифры только сознательным
  действием админа.
- Спам-фильтр (правила, белые/чёрные списки, веса проверок) настраивает админ на весь
  сервер. Пользователь в клиентах только помечает «спам / не спам».

**Пользователь (веб)**
- Убираем: чтение почты, отправку, поиск, «Удалённые» (vault), список писем «Спама»,
  просмотр событий и контактов.
- Остаётся: мои учётки (внешние ящики, календари CalDAV/ICS, адресные книги CardDAV —
  подключение и настройки), журнал синхронизации, профиль (язык, пароль, ключ
  восстановления, пароли приложений).

## Этапы

1. **Админ отдельно.** Тип учётки «администратор»; `/admin` и `/api/admin/*` пускают только
   её; журнал действий админа; ограничение `/admin` по IP (настройка, по умолчанию выкл).
   Перенос: на нашем сервере завести учётку администратора, у `lucky` снять флаг.
2. **Блокировка везде.** Проверка `is_banned` на всех протоколах и при выдаче токенов;
   разрыв сессий (WebSocket, IMAP IDLE).
3. **Ящики с паролем.** Пароль у ящика локального домена; IMAP/SMTP-вход ящиком;
   подключение локального ящика как учётки с распознаванием «это наш сервер»; перенос
   текущих ящиков владельца (`info@help-it-audit.ru` и др.) без потери писем.
   Самый крупный этап — перед началом отдельный подробный план.
4. **Админ: домены и ящики.** Все домены и ящики сервера, DNS-записи домена,
   создание/отключение/удаление ящика, смена пароля ящика.
5. **Админ: пользователи.** Ссылки-приглашения, список, блокировка, удаление,
   одобрение при предмодерации.
6. **Настройки сервера.** Режим регистрации (в `system_settings`, без перезапуска;
   `security.disable_registration` в config — значение по умолчанию), спам-фильтр сервера,
   лимиты (всё выключено по умолчанию).
7. **Чистка пользовательского веба.** Удалить страницы чтения/отправки; перед удалением
   проверить по коду клиентов, что они эти маршруты не зовут.

Каждый этап — отдельный коммит с тестами и выкаткой; поведение пользователя меняется
только на этапах 3 и 7.
