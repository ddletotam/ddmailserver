# Мобильные клиенты: внешние учётки (IMAP/SMTP, CalDAV/CardDAV)

Общий контракт для Android (`mobile/android`) и iOS/iPadOS/macOS (`mobile/ios`).
Решение владельца 2026-11-12: **каждый клиент обязан поддерживать и обычные
IMAP/SMTP-ящики, и сервер ddmail; цель — полный аналог десктопа.** Публикация
(RuStore, App Store) — только после этого.

Источник смысла — десктоп (`desktop/core/src/{imap,imap_provider,smtp,discover,oauth,caldav_client,carddav_client}.rs`,
`docs/desktop-behavior-contract.md`). Ниже — **что** обязано совпадать с ним, и где
мобильные клиенты делают **лучше**: у десктопа найдены слабые места (полный
пересинк, нет копии в «Отправленных», нет UIDVALIDITY), повторять их нельзя.
Платформенные «как» — в контрактах клиентов (`android-behavior-contract.md`,
`ios-behavior-contract.md`, раздел «Внешние учётки»).

## 1. Учётки

- **Несколько учёток одновременно**, любых видов вперемешку:
  - `ddmail` — сервер ddmail, токен сессии (как сейчас);
  - `imap` — IMAP + SMTP, вход паролем (в т.ч. паролем приложения);
  У любой учётки могут быть свои CalDAV/CardDAV (§8); у ddmail они — сервер.
- **Ключ учётки** `account_key` = `username@host` IMAP (`imap::account_key` десктопа);
  у ddmail — как сейчас. Беседа идентифицируется парой (`account_key`, `id`):
  одинаковые id в разных учётках — разные беседы. В кэше первичный ключ включает
  `account_key` (у десктопа — нет, это его ошибка).
- **Первый запуск и «Добавить учётку»** — одно и то же окно: email → поиск (§2) →
  нашёлся ddmail — вход на сервер; иначе — найденные IMAP/SMTP и пароль; «Я знаю
  все настройки» — ручная форма (IMAP хост/порт/TLS, SMTP хост/порт/TLS,
  логин, «SMTP без авторизации»). Перед сохранением — проверка входа на IMAP
  и SMTP (у каждого шага таймаут 25 с), ошибка — по-русски («неверный логин или
  пароль», «сервер не отвечает», текст TLS-ошибки как есть).
- **Настройки → Учётки:** список, правка, повторный вход, удаление (удаляет
  секреты и кэш учётки), CalDAV/CardDAV-адреса.
- **Секреты:** пароль IMAP-учётки хранится — без него нет фона. Android —
  зашифрованно ключом Android Keystore (как токен, `android §2`); Apple —
  Keychain `AfterFirstUnlockThisDeviceOnly`. Открытым текстом — никогда (деградации
  десктопа `plaintext_secrets` у мобильных нет). Пароль никуда, кроме своих
  IMAP/SMTP/DAV-серверов, не уходит.
- **152-ФЗ:** хранение пароля и прямое соединение с почтовыми провайдерами
  меняют политику конфиденциальности (`deployments/privacy.html`) — новая
  редакция только с согласия владельца, до публикации.

## 2. Автонастройка

Порт `desktop/core/src/discover.rs` целиком: фазы, порядок кандидатов,
`mx_provider`, `mail_presets`, разбор autoconfig, таймауты (TCP 3 с, ответ 8 с),
«побеждает первый успешный по порядку доверия», отмена между фазами, прогресс
от верхней границы числа проверок. Пароль при поиске не уходит; открытый текст
не принимается (IMAP 143 — только со STARTTLS, `socketType=plain` отвергается,
SMTP 25 на MX не пробуется). MX — системным резолвером (как сейчас у ddmail-поиска).
Тестовые случаи — из тестов `discover.rs`.

## 3. IMAP: синхронизация (лучше десктопа)

- **Папки** — по SPECIAL-USE (`\Sent`, `\Drafts`, `\Junk`, `\Trash`), иначе по
  именам как `find_sent_folder` десктопа (плюс аналогичные списки для Junk:
  `Junk`, `Spam`, `INBOX.Junk`, `INBOX.Spam`, `Спам`). Имена — modified UTF-7.
  Синкаются INBOX, Sent, Drafts и **Junk — как папка «Спам»** (у десктопа спама
  для IMAP нет; у мобильных он есть и должен работать для любой учётки).
- **Окно:** последние 5000 INBOX, 2500 Sent, 1250 Drafts, 500 Junk (лимиты десктопа),
  по UID, не по номерам.
- **Инкрементально, по состоянию папки** (`UIDVALIDITY`, `UIDNEXT`,
  `HIGHESTMODSEQ`) в кэше:
  - сменилась `UIDVALIDITY` → кэш папки (заголовки и тела) выбросить, папку заново;
  - новые письма — `UID FETCH <последний+1>:*`;
  - флаги — `CONDSTORE` (`CHANGEDSINCE`), без него — `UID FETCH 1:* (FLAGS)` окна;
  - удалённые — `QRESYNC`/`VANISHED`, без него — `UID SEARCH ALL` и разница.
  Полный пересинк на каждый проход (как у десктопа) запрещён.
- **Заголовки:** `UID FLAGS ENVELOPE INTERNALDATE BODY.PEEK[HEADER.FIELDS (FROM TO CC DATE SUBJECT MESSAGE-ID IN-REPLY-TO REFERENCES CONTENT-TYPE)]`.
  `From` — из сырого заголовка (регистр имени), RFC 2047 декодируется.
  Дата — `Date`, не разобралась — `INTERNALDATE`.
- **Беседы строятся на устройстве из кэша заголовков** — порт
  `fetch_conversations_impl`/`conversation_participants`/`conversation_id`
  десктопа (`desktop/core/src/imap.rs`), обязан совпадать **байт в байт** с ним и
  с `internal/web/handlers_desktop.go` (ящик может приехать обоими путями):
  набор = From+To+Cc в нижнем регистре, без Bcc; роли; `my_id` по первому
  письму; label группы `"<тема> (<N> чел)"`; дубли по Message-ID (копия из Sent
  побеждает); черновики отдельно; `unread_count`; `avatar_hash`; `received_by`.
  **Отличие:** группировка — по готовому id, а не по набору; так входящее по bcc
  (`{bob}`, id `me|bob`) и наш ответ (`{me,bob}`, тот же id) — одна беседа, а не
  две строки с одним id (ошибка десктопа). Тесты — порт тестов `imap.rs` и
  `handlers_desktop_test.go` по этой функции.
- **«Свои» адреса** — email учётки, её логин, если он адрес, и адреса,
  добавленные пользователем как айдентики учётки (настройки учётки: «Другие мои
  адреса» — без сервера ddmail айдентики больше взять неоткуда).
- **Тела** — `UID FETCH (BODY.PEEK[])` (флаг `\Seen` не ставится), разбор MIME на
  устройстве в ту же модель тела, что даёт сервер ddmail (html, text, вложения
  с индексами, части по `cid:`), чтобы лента (`mobile/shared/conversation-doc`)
  не знала, откуда письмо. Кодировки — все, что встречаются в RU-почте
  (UTF-8, windows-1251, koi8-r, iso-8859-*), QP/base64, RFC 2047/2231. Подкачка
  заранее и выбор пользователя «Всегда / Wi-Fi / Нет» — как у ddmail.
  Части `cid:` работают (у десктопа для IMAP — нет). Вложения — по запросу,
  из кэша сырого письма или повторным `BODY.PEEK[]`.

## 4. IMAP: изменения

Оптимистично в кэше, затем запрос; отказ — откат и сообщение (как у ddmail).
- **Прочитано/непрочитано** — `UID STORE ±FLAGS.SILENT (\Seen)` по папкам писем
  беседы; ошибка не глотается (у десктопа — глотается).
- **Удаление** — `\Deleted` + `UID EXPUNGE` (UIDPLUS), иначе `EXPUNGE`.
  Необратимо, как у десктопа и как у мобильных для ddmail — с тем же подтверждением.
- **«В спам»** — `UID MOVE` в Junk (без MOVE — `UID COPY` + удаление). Без правил
  «адрес/домен»: их держит только сервер ddmail, в диалоге одна кнопка «В спам».
  Нет папки Junk — пункта нет. **«Не спам»** — перенос из Junk в INBOX.
- **Папки диалогов** — если есть ddmail-учётка, её серверные папки; иначе —
  локальный документ на устройстве в том же формате (как `dialog_folders.json`).

## 5. SMTP

- TLS: 465 — неявный TLS, 587/25/2525 — STARTTLS (обязателен; сервер без него —
  ошибка, открытым текстом не шлём). Сертификат — системным хранилищем (§10).
- AUTH: PLAIN/LOGIN паролем; «без авторизации» по флагу.
- MIME — как десктоп: `multipart/alternative{text,html}`, `related` для
  встроенных картинок, `mixed` для файлов; `Message-ID <hex.hex@домен-from>`,
  `In-Reply-To`/`References` в ответах. Bcc не пишется в заголовки.
- **Копия в «Отправленные» (у десктопа нет):** через ~5 с после отправки —
  `UID SEARCH HEADER Message-ID` в Sent; не нашлась за ~15 с — `APPEND` в Sent
  с `\Seen`. У Gmail не делать (кладёт сам).
- From по умолчанию — айдентика беседы (`received_by`); учётка для отправки —
  владелец адреса From (как `owner_for` десктопа); нет владельца — «Не через что
  отправить». Optimistic send — как у ddmail.

## 6. Новая почта и фон

- **На экране:** IMAP IDLE на INBOX каждой учётки (своё соединение), перевыдача
  IDLE каждые 25 мин, обрыв — переподключение с бэкоффом (не чаще раза в 30 с).
  Событие → инкрементальный синк (§3). Без IDLE у сервера — опрос раз в 2 мин.
- **В фоне:** push у внешних учёток нет. Периодический синк ОС (Android —
  WorkManager ~15–30 мин; Apple — BGAppRefresh) по всем IMAP-учёткам;
  локальное уведомление с отправителем и темой — та же логика и те же правила
  тишины (спам, скрытые папки), что у ddmail.

## 7. Ошибки

- **Неверный пароль** (`NO [AUTHENTICATIONFAILED]`/`NO` на LOGIN, SMTP 535) → состояние **«нужен вход» для этой учётки** — плашка с
  «Войти» (форма с паролем), ретраи его не лечат (у десктопа такого состояния для
  IMAP нет — он молча переподключается каждые 30 с). Кэш учётки виден.
- Сеть/таймаут — временное, бэкофф. Ошибка одной учётки не мешает другим.

## 8. CalDAV / CardDAV

Порт `caldav_client.rs`/`carddav_client.rs`: обнаружение (`.well-known/caldav`,
`current-user-principal` → `calendar-home-set`/`addressbook-home-set`), чтение
`REPORT` с time-range, запись `PUT If-None-Match`/`If-Match`, удаление
`DELETE If-Match`, vCard через `build_vcard`. **Лучше десктопа:** все календари
home-set, а не первый; часовые пояса `TZID`/`VTIMEZONE` — по базе ОС, не «как UTC».
Авторизация — Basic паролем учётки. Элементы помечены
`account_key`, в общем календаре/контактах — вместе с ddmail. Адреса DAV
находятся автоматически по домену при добавлении учётки, правятся в настройках.

## 9. Google OAuth — не делаем

Решение владельца 2026-11-12: отдельного OAuth-приложения Google для мобильных
клиентов не будет. Gmail подключается как обычный IMAP паролем приложения.
Кнопки «Войти через Google» нет; XOAUTH2 в мобильных клиентах не нужен.

## 10. TLS

Системное хранилище доверия (Android — включая пользовательские CA, как для
ddmail), TLS 1.2+, без исключений и без «доверять всё равно». Ошибка — текстом.

## 11. Проверка

- Юнит-тесты: построение бесед (порт тестов десктопа и сервера), разбор IMAP-ответов
  (литералы, ENVELOPE, modified UTF-7), MIME (кодировки, вложения, cid), autoconfig,
  инкрементальный синк на записанных сессиях (смена UIDVALIDITY, VANISHED, без CONDSTORE).
- Вживую: тестовый ящик Mail.ru (`CLAUDE.local.md`, пароль приложения) и учётка
  `lucky` на `mail.letotam.ru` **по IMAP** (тот же ящик, что через ddmail, — беседы
  обязаны совпасть по id). Письма с реальных адресов владельца не отправлять без
  его согласия; отправку проверять письмом самому себе.
