# Аудит Android-клиента ddmail — 2026-11-14

Объект: `mobile/android` из `main` (`49c2dcf`, версия 0.0.33). Мерки — те же, что у аудита Apple-клиента
(`docs/audit/ios-audit-2026-11-13.md`): каждая из его 40 находок проверена применительно к Android — есть ли та же
проблема или та же недостающая функция. Исправления — в этой ветке, версия поднята до **0.0.34**.

Эталон, по убыванию силы: `docs/mobile-layout.md` → `docs/desktop-behavior-contract.md` и код десктопа
(`desktop/native/ui/app.slint`) → `docs/android-behavior-contract.md` → `docs/mobile-external-accounts.md` →
Apple-клиент (`mobile/ios`, только чтение) для сравнения решений.

## Как проверялось

- **Статически:** весь `mobile/android` (≈21 тыс. строк) против контрактов и iOS-аудита; общий документ ленты
  `mobile/shared/conversation-doc` — только API (`ddm.remove`, `ddm.view`), документ не менялся.
- **Тесты:** `./gradlew testHmsDebugUnitTest test assembleHmsRelease assembleHmsDebug` — зелёные (все модули,
  новые: `VCardEditTest` — порт тестов `internal/carddav/vcardedit`, `MessageSourceTest`, `FeedRemovedTest`, три
  новых в `DdmailApiTest`).
- **Живьём:** Huawei Mate XT (GRL-LX9, EMUI 14, разложен на два экрана — 712 dp, колонка + беседа), релизная
  сборка 0.0.34 поставлена поверх 0.0.31 (`adb install -r`, данные не тронуты). Учётки на телефоне: `lucky`
  (ddmail) и `denis.danilin@internet.ru` (IMAP, Mail.ru).
- **Снимки:** `~/.cache/ddmail-android/screens/` на станции (вне git: на снимках ПДн — 152-ФЗ).
- **Что сделано в данных:** отправлены два письма самому себе на `info@help-it-audit.ru` с IMAP-учётки
  («Proverka ddmail udalenie 0.0.34 013543», «Proverka ddmail uvedomlenie 0.0.34 013945»; тема — «Re: Проверка
  ddmail 20261113-140714 imap»: ответ в беседе). Первое удалено «Удалить письмо» (копия в «Отправленных» Mail.ru);
  его входящая копия в ящике `lucky` («Проверка push») осталась. Беседа «Проверка push» открыта из уведомления —
  отмечена прочитанной. Другого не удалялось и не правилось; «Поделиться» закрыт без выбора получателя.
- **Не проверено живьём:** падение процесса отрисовки WebView (без root его не убить), переподключение
  WebSocket после обрыва сети, возврат неотправленного в свою беседу (нужен отказ сервера), предупреждение о
  запрещённых уведомлениях (на телефоне они разрешены), правка внешнего CardDAV-контакта (у IMAP-учётки на
  телефоне нет CardDAV). Эти пункты проверены по коду и тестам; где вывод держится только на коде, это сказано.

## Решения по спорным местам (владелец отсутствует)

1. **Меню пузыря — диалог, а не меню у пузыря.** iOS перешёл на системное контекстное меню у пузыря (S-04). На
   Android мост не получает координат пузыря: у `@JavascriptInterface` число аргументов — часть подписи, и
   добавлять вторую подпись в общий документ ради позиции меню — лишний риск совместимости с iOS. Меню осталось
   диалогом посреди экрана (так и было), пункты — как у десктопа; «Показать…» раскрывается на месте.
2. **«Удалить письмо» в беседе из одного письма** удаляет письмо и закрывает беседу (она уходит целиком, как у
   iOS и надгробий журнала).
3. **«Исходник сообщения» огромного письма** показывается началом (256 тыс. символов), «Скопировать» берёт всё —
   как iOS.
4. **Правка контакта внешней CardDAV-книги.** Аудит iOS (S-14) говорил только о сервере ddmail; на Android
   найдено то же самое и хуже на прямом CardDAV IMAP-учёток: карточка пересобиралась из полей формы и теряла
   фото, адреса, заметки. Портирована серверная правка по строкам (`VCardEdit`), а не урезание.
5. **«Внешний контент»** — отдельный экран из строки «Настроек», а не раздел внутри: список отправителей бывает
   длинным, а «Настройки» Android — одна прокрутка.
