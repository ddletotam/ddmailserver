## Почему вообще

WebView2/Ultralight дают горизонтальное переполнение: широкая письменная вёрстка
вылезает за пузырь. Требование к своему рендеру — результат **никогда** не шире
`width * scale`; широкое масштабируется/переформатируется, но не обрезается
с overflow.

## Разделение работ

| Компонент | Кто | Что |
|---|---|---|
| `desktop/emlrender` | Opus | HTML письма → RGBA-битмап + геометрия (ссылки, текстовые прогоны). Без браузерного движка. |
| `desktop/render-lab` | Opus | Стенд на Slint: читает кэш клиента, гонит каждое письмо через `emlrender`, рисует бабблы подряд в одной скролл-панели. Выделение и клики по ссылкам — здесь, поверх геометрии от рендера. |

## Ключевое следствие из п.6

Битмап сам по себе не умеет ни выделяться, ни кликаться. Поэтому `Rendered`
возвращает не только пиксели, но и геометрию:

- `links: Vec<LinkBox>` — прямоугольник + `href`, для hit-теста клика и курсора;
- `text: Vec<TextRun>` — прямоугольник + строка + x-позиции границ символов,
  чтобы стенд считал выделение, подсветку и копирование в буфер.

Координаты — в CSS-px относительно левого верхнего угла битмапа (умножать на
`scale` для пикселей). Это расширение замороженного API — согласовано здесь,
менять только вместе с `render-lab`.

## Критерий готовности

Стенд открывает весь закэшированный инбокс, все письма отрисованы, ни одно не
вылезает по горизонтали, скролл плавный, текст выделяется, ссылки кликаются,
и выглядит это хорошо.
