# Документ ленты беседы

Общий для мобильных клиентов (Android — WebView, будущий iOS — WKWebView)
документ, в котором рисуется лента пузырей открытой беседы. Устройство и
требования — `docs/android-behavior-contract.md` §8.

- `conversation.html` — каркас документа и CSP;
- `conversation.css` — обвязка пузырей (вне shadow root писем);
- `bubble.css` — стили внутри shadow root каждого письма;
- `conversation.js` — мост с нативным кодом, окно отрисовки, нормализатор
  (чистка, цитаты, картинки, масштабирование широких писем).

## Выделение текста

Долгое нажатие на пузырь занято меню письма, поэтому выделение начинается
серией тапов, как у десктопа (§4в «Серия кликов»): **двойной тап** — слово,
**тройной** — фраза (предложение по `Intl.Segmenter`; без него — строка до
переноса, то есть абзац или строка письма). Дальше — системные маркеры
(тянуть, чтобы расширить) и системное «Скопировать». Одиночный тап открывает
ссылку и вложение, как раньше; двойной тап не масштабирует
(`touch-action: manipulation`), щипок — масштабирует.

Как устроено (`wireTapSeries` в `conversation.js`):

- Серия: тапы ≤ 350 мс, сдвиг ≤ 10 px, пауза между тапами < 400 мс, в одно
  место (≤ 30 px). Клики серии гасятся — двойной тап по ссылке не открывает её
  второй раз (первый тап — обычный, ссылку открывает).
- Тело письма — в закрытом shadow root: точку в символ переводит
  `caretPositionFromPoint(x, y, {shadowRoots})`, где его нет — поиск символа
  по прямоугольникам среди текста под `shadowRoot.elementFromPoint`. Границы
  ищутся в тексте ближайшего блока; `<br>`, вложенные блоки и свёрнутые
  цитаты — жёсткие переносы. Выделение ставится `setBaseAndExtent`.
- **WKWebView (iPhone/iPad):** тап серии гасится на `touchend`, выделение
  ставит скрипт. Маркеры WebKit рисует сам, а меню — нет: документ зовёт
  `selectionMenu(x, y, w, h)`, и нативная часть показывает над выделением
  «Скопировать» (`UIEditMenuInteraction`), текст берёт `ddm.selectedText()`
  (`getSelection().toString()` у WebKit внутри shadow root пуст). После того
  как маркер взяли, меню показывает уже сам WebKit («Скопировать / Найти /
  Перевести»).
- Клавиатура открыта (фокус в строке ввода): первый тап по письму её
  убирает, а второй WebKit документу не отдаёт и выделяет слово сам — без
  меню и без `selectionchange`. Нативная часть сообщает о клавиатуре
  (`ddm.keyboard(on)`); когда она ушла, документ секунду смотрит, не появилось
  ли выделение в письме, и просит к нему меню.
- Долгое нажатие на iPhone/iPad (450 мс, своё — WebKit `contextmenu` не шлёт):
  пока палец держат, документ без `user-select` (`holdNativeSelection`) —
  иначе WebKit следом начинал своё выделение с меню поверх меню письма.
- **Android WebView:** выделение из скрипта Chromium рисует без маркеров и
  меню, а тап по уже выделенному тексту их показывает (и шлёт `contextmenu`).
  Поэтому выделение ставится на `touchstart` тапа серии, а `contextmenu`
  после тапа по выделению onLongPress пропускает системе. Долгое нажатие
  (палец ещё на экране) — по-прежнему меню письма; выделение при этом снимается.
- Палец у маркера (≤ 36 px от начала/конца выделения, по
  `getComposedRanges`) — на iPhone/iPad долгое нажатие не перехватывается:
  маркер тянут.
- Мышь и трекпад (Мак, iPad с трекпадом) серией не заняты: двойной и тройной
  клик выделяют средствами движка.

## Меню пузыря и чипа

`bubbleMenu(uid)` и `attachmentMenu(uid, index)` — как раньше на Android.
WKWebView (`askMenu`) добавляет шесть чисел: прямоугольник пузыря (чипа) и
точку нажатия в CSS px от начала документа — iPhone/iPad показывают
системное меню у пузыря, а не посреди колонки. Android их не получает: у
`@JavascriptInterface` число аргументов — часть подписи метода.

Для пунктов меню нативный код может звать (оба необязательны, проверять
`ddm.remove && …`):

- `ddm.remove([uid])` — письма удалены: пузыри и разделитель дня без писем уходят;
- `ddm.view(uid, 'text' | 'html')` — текстовая версия письма вместо HTML и
  обратно (до следующего `ddm.set`).

Проверка в headless Chromium: строгий мост «как Android» (лишний аргумент —
ошибка) и мост WebKit — оба зелёные (2026-11-13).

Клиенты кладут каталог в свои ресурсы при сборке; правится только здесь.
Сменил нормализацию — подними `NORMALIZER_VERSION` в `conversation.js`.
